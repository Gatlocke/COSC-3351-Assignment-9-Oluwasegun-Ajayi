# Assignment 9 — PostgreSQL REST API

This project extends the Assignment 8 Express API with persistent PostgreSQL
storage. The required routes are now **`/api/items`**, not `/api/resources`.
The five routes execute SQL directly; there is no local-array fallback.

## Requirements

- Node.js 22.10 or newer; Node 24 LTS recommended
- PostgreSQL, locally or hosted, with permission to create a schema/table
- An environment variable named `DATABASE_URL`

The database connection is never bundled with the project. Keep credentials
in your environment or a local `.env` file, which is excluded from Git.
`.env.example` contains only a local, password-free example, not a real
hosted connection string.

## Local setup on a Mac

1. Install Node.js and PostgreSQL. Postgres.app is one local PostgreSQL option.
2. Start PostgreSQL and create a database named `assignment9`. If using
   Postgres.app, its command-line tools can be added for the current Terminal:

   ```sh
   export PATH="/Applications/Postgres.app/Contents/Versions/latest/bin:$PATH"
   createdb assignment9
   ```

3. Open Terminal in the extracted **Assignment 9** folder:

   ```sh
   npm ci
   cp .env.example .env
   ```

4. Edit the local `.env` if your PostgreSQL host, port, database name, or
   credentials differ. The example assumes PostgreSQL on localhost:5432
   using your macOS account. For a hosted database, use the provider's
   connection configuration and required TLS settings.
5. Create the development/local table, then start the API:

   ```sh
   npm run db:setup
   npm start
   ```

   Setup uses `CREATE ... IF NOT EXISTS`; it preserves existing rows.
   The API checks that the table exists but does not create or migrate it
   during startup.

6. In a second Terminal, check:

   ```sh
   curl -i http://localhost:3000/api/items
   ```

When `DATABASE_URL` is already supplied through the runtime environment,
no `.env` file is necessary. Stop the API with Control+C. Restarting it
does **not** clear the saved items. If port 3000 is occupied, use
`PORT=3001 npm start` and update the client URL.

## Database and data model

PostgreSQL suits the fixed task fields and provides database-generated IDs,
constraints, persistent storage, and parameterized SQL operations.
`db/schema.sql` defines the dedicated `assignment9.items` table:

| Field | PostgreSQL type | Rule |
| --- | --- | --- |
| id | INTEGER, generated identity | Primary key; generated by PostgreSQL |
| title | VARCHAR(120) | Required, nonblank, maximum 120 characters |
| completed | BOOLEAN | Required, default false |

Request titles are trimmed. Null characters, unknown fields, user-supplied
IDs, incorrect data types, and empty updates are rejected.

## Endpoint contract

| Method | Path | Success | Missing item |
| --- | --- | --- | --- |
| GET | `/api/items` | 200, array of database rows | Not applicable |
| GET | `/api/items/:id` | 200, database row | 404 |
| POST | `/api/items` | 201, inserted row; Location header | Not applicable |
| PUT | `/api/items/:id` | 200, updated row | 404 |
| DELETE | `/api/items/:id` | 200, deletion message and removed row | 404 |

POST body:

```json
{
  "title": "Review database-backed endpoints",
  "completed": false
}
```

PUT accepts `title`, `completed`, or both. Unspecified fields retain their
database values. Invalid bodies or IDs return 400; oversized JSON returns
413; database failures return a sanitized 503 rather than fake success.
All responses are JSON. There is no frontend or root homepage.

## Structure and safety

- `app.js`: Express routes, JSON parsing, request logging, error responses
- `validation.js`: allowed fields and input checks
- `db/pool.js`: PostgreSQL connection pool with timeouts
- `db/schema.sql`, `db/setup.js`: explicit local/development schema setup
- `server.js`: checks database readiness and starts/stops the API
- `requests.http`: ready-to-run VS Code REST Client requests
- `test/api.test.js`: real-database integration tests and an error-path check
- `scripts/evidence.js`: records actual HTTP/SQL results in `TESTING.md`

Values are bound to `$1`, `$2`, etc., rather than concatenated into SQL.
UPDATE and DELETE target the database ID, with `RETURNING` used to confirm
the affected row. Request logging runs before JSON parsing. Neither API
errors nor startup failures print database passwords or connection strings.

## Verification

After local/development database setup:

```sh
npm test
npm run evidence
```

The tests insert their own rows and clean up only those rows. They never
truncate the table or clear pre-existing items. Restart tests use actual
Node server processes against the same database and check both persistence
and permanent deletion.

`TESTING.md` contains captured automated HTTP responses, direct SQL
verification, and restart evidence. `requests.http` can be opened using the
VS Code REST Client extension to capture client-specific response evidence.

`evidence/SETUP.md` records the supplied local Mac setup output.
`evidence/CLIENT-RESULTS.md` contains all eight verified client response captures.
`evidence/MAC-TESTS.md` records the Mac test summary and report-generation output.
These files and screenshots placed in `evidence/` are not overwritten by
`npm run evidence`; the generated `TESTING.md` links to them.
